📒Meeting Outline

CAMS Documentation and Symlink Usage

• Symlink Integration  
  The team uses a symlink approach to integrate the CAMS documentation repository into multiple repos. This allows all agents and tools to access shared context and updates seamlessly without duplicating files. The symlink is a one-time setup per environment and automatically reflects updates across repos.

• Credential Management and Access  
  Credential stores are maintained for accessing various services like WPI APIs, Jira, Confluence, and Bitbucket. These credentials include service account profiles and user-specific SIDs stored securely in OS keychains. Git credentials are also leveraged for push/pull operations, with "remember me" functionality ensuring smooth authentication.

Deployment and SRE GKP Agent

• Deployment Helper Skill  
  A helper skill simplifies deployments by checking branch existence and providing build options specific to DSP ITC. It triggers builds via the Joe's API, streamlining release team workflows by reducing repetitive manual steps.

• SRE GKP Agent for Debugging  
  The SRE GKP agent manages cluster environment details and can fetch logs or perform analysis on specified clusters and applications. It automates debugging by identifying configuration issues or missing properties, reducing manual troubleshooting effort.

• Environment and Application Metadata  
  Metadata files define WPI environments, clusters, and applications with short names for easy reference. These are auto-generated to maintain consistency and support agent operations.

Agent Configuration and Workflow Automation

• Project-Specific Standards and Safety Rules  
  Agents require project-specific configurations such as resource naming conventions, config map usage, and safety rules for handling ambiguous situations. Workflows define step-by-step processes for tasks like modifying config maps and restarting applications, with options to persist changes centrally to avoid overwrites during deployments.

• Platform Architect Agent and Subskills  
  The platform architect agent integrates three subskills: PR Reviewer, Impact Analyzer, and Dependency Builder. Together, they provide comprehensive reports on PR changes, their impact on the ecosystem, and dependency relationships.

PR Reviewer Skill and Workflow

• PR Review Process  
  The PR Reviewer skill fetches PR metadata from Bitbucket, checks out the source branch locally, and performs diffs against the target branch. It applies CAMS coding standards, verifies test coverage, and generates detailed reports highlighting issues and recommendations.

• Branch Management and Updates  
  The agent ensures the local repo is updated by pulling the latest changes from the remote branches before analysis. It handles cases where branches may not exist locally by fetching them as needed.

• Posting Review Comments  
  Review comments are generated locally and can be optionally posted directly on Bitbucket PRs using configured Bitbucket API tokens. Credentials for these operations are managed securely via the ID Anywhere Auth skill, which does not store passwords in checked-in files.

Dependency Graph and Impact Analysis

• Static Code Analysis and Dependency Mapping  
  Using Copilot, the team has created dependency graphs for WPI repos showing API calls and event flows. These graphs help visualize the blast radius of changes, identifying all impacted components and enabling better regression testing scope definition.

• UI for Dependency Visualization  
  A React-based UI allows users to explore high-level and detailed dependency graphs, including API relationships and eFire event flows. This aids in understanding the impact of code changes across the microservice ecosystem.

• Future Enhancements  
  Plans include enriching static analysis with telemetry data and extending impact analysis to upstream dependencies beyond the WPI ecosystem.

Skills Management and Collaboration

• Skill Repository and Reusability  
  Skills are maintained in a common repository (CAMS documentation repo) and shared via symlinks to avoid duplication. Teams are encouraged to identify reusable skills, modify them as needed for their specific context (e.g., TSP, ITC), or rewrite where necessary.

• Local Development and QA Enablement  
  Some skills, such as the Admin Center Data Sync skill, are developed locally to automate frequent manual tasks. Challenges include managing credentials and environment setup for QA teams, with ongoing efforts to automate these processes.

• PR Standards Learner Skill  
  This skill helps update coding standards by analyzing peer review comments and incorporating new rules automatically, ensuring standards evolve with team practices.

Security and Best Practices

• Credential Handling and Guardrails  
  Emphasis on secure credential management to prevent incidents like the Pocket OS production data loss. Production environments do not use password-based access, and credentials are never stored in checked-in skill files.

• Avoiding Plain Text Exposure  
  Concerns raised about tools like Cloud Code exposing user IDs and passwords in plain text on consoles, highlighting the need for secure handling.

General Discussion and Recommendations

• Reducing Manual Repetitive Tasks  
  The session emphasized automating mundane tasks using Copilot and skills to increase productivity and reduce defects.

• Repository Structure and Symlink Use  
  For TSP and ITC, aggregated workspaces might reduce the need for symlinks, but symlinks remain valuable for managing multiple repos and sharing common configurations.

• Community Collaboration  
  Encouragement to share relevant skills across teams and maintain a common repository for easier access and updates.

• Human in the Loop  
  Despite automation, human oversight remains critical to validate agent outputs and avoid false positives.

• Acknowledgments  
  Recognition of significant contributions from a few active team members driving the development and sharing of skills.
