📒Meeting Outline

Sprint Planning and Resource Management

• Sprint Start and Planning
  The team confirmed starting sprint planning with updates on tasks and resource availability. Raksha informed that the DBA partner is out of office until September 1, creating a potential blockage for database changes needed to support new features like B40, B45 details storage. Raksha will reach out to alternate contacts to mitigate this risk.

• Task Prioritization and Dependencies
  Several tasks related to UI updates, backend pipelines, and database changes were discussed. Pending tasks include enabling radio button flows, adding new columns for B40/B45, and segregating backend DQ rule processes. Some tasks are on hold due to dependencies on DBA support. The sprint end date is August 31, with efforts to prioritize critical tasks to meet this deadline.

• Status Updates and Workflow Enhancements
  The team agreed to mark task statuses clearly (e.g., "in build") to improve visibility. A new UI tab will be created to separate approved/rejected records from new requests to avoid confusion. Kundan is assigned to backend and UI tasks related to approval/rejection flows, including renaming UI labels for clarity ("Reason for approval/rejection").

Reporting and Dashboard Development

• Q-Track Reporting MVP
  Sachin explained the MVP for Q-Track reporting, which integrates data from DQIM and DQ results to provide downloadable reports filtered by use case and time period. The initial version will be a simple Excel report sent via email, with a future dashboard planned for visualizations.

• Resource Constraints and Timeline
  Front-end resource constraints were highlighted, with only one front-end developer (Athar) available. Backend development can proceed with additional resources, but full UI integration will be delayed beyond the current sprint. The team agreed to deprioritize some self-serve features to accommodate this.

• Platform and Deployment Challenges
  Sachin outlined the need for platform reviews, SRE approvals, and ALM requests for deployment, making a launch by August 31 unlikely. Discussion included the possibility of storing data outside Lumi (ACE database) to overcome data retention limitations and support longer time periods (90+ days). This requires building new transaction tables and involves significant design and review effort.

Data Quality (DQ) Rules and Framework Updates

• CD Rules and Role Modifications
  Ongoing work on CD rules continues with ANSI and Suman covering while IFI is on leave. Rishabh will be the point of contact for new role additions and sign-offs. Some rules require rewriting based on alert feedback.

• DQIM Framework and Calibra API Integration
  Both metadata usage logs and KRI frameworks are implemented, but outputs are stored separately and need integration. Calibra API integration requires discovery and is planned for the next sprint due to dependency on integration ID requests.

• Multivariate and Univariate Rules
  Varga continues work on multivariate generic rules. Univariate monthly builds are complete; daily builds are near completion with a demo planned. Stories are reserved for Sameer to support this.

Data Pipelines and Environment Access

• Pipeline Deployment and Validation
  Jason and Sravan discussed deployment of data ingestion pipelines. Four pipelines are deployed but require validation; eight pipelines remain to be certified and deployed. Access issues with service IDs and vault configuration are blocking some tasks.

• Environment Provisioning and Cost Estimates

• Pipeline Capacity and Story Point Estimation
  Jason estimated story points needed to complete remaining pipelines and certification. Sachin plans to assign tasks accordingly.

Automation and SQL Execution Tasks
