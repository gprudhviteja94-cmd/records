Reporting and Data Quality (DQ) Rule ID Migration Challenges

Enhancements and UI/UX Discussions

• Register DQ Rule Page Enhancement  
  The request to add a "Previous Page" button was clarified as redundant since a "Back" button already exists. This enhancement was dropped.

• Date Filter Functionality in DQ Review Alerts  
  The current date filter only applies to the data loaded on the UI page and does not support API-level filtering by run date or date range. This limitation means users cannot retrieve all alerts for a selected date range, only those present on the current page.

• API Limitation and Future Fixes  
  The API used by the GCS team lacks run date filtering capability, causing the date filter to be ineffective. The team agreed to escalate this issue to Bhagwan for resolution, copying Rajendra and Sravan for follow-up. Sravan will discuss this with Bhagwan in person to emphasize the business need and future scalability concerns.

• Approval Project Enhancement  
  The enhancement to enable a text field for rejection reasons was confirmed as implemented via a note update mechanism.

Technical and Operational Updates

• Direct Call to Lumi for Query Execution (POC)  
  Rajendra suggested a potential improvement to bypass SFTP dependency by making a direct call from ACE to Lumi for query execution before creating a human task. Sachin will explore this feasibility with the Lumi team, noting it will require time and is not an immediate fix.

• Database Connection Management  
  Kundan highlighted issues with idle database connections causing resource problems. Team members were reminded to disconnect their database sessions at the end of the day to avoid exceeding connection pool limits.

• DQID Cleanup and Data Validation  
  The team is finalizing data validation and cleanup activities related to DQIDs, focusing on missing records and updating related repositories. The cleanup is targeted for completion by Friday, with migration to environment E1 followed by RFCs for promotion to E2 and E3.

• Pipeline Certification and Timestamp Field Issue  
  Sravan reported a pipeline certification delay due to timestamp fields being marked as strings. He plans to revert these to datetime to meet Lumi team requirements.

• Communication and Issue Escalation  
  Team members were encouraged to post challenges on the development group or email to ensure timely follow-up by IFR or NC teams, rather than waiting for scheduled DSUs.
