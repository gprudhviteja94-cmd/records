📒Meeting Outline

Product Increment 26.3 Planning and User Story Review

• DQIM Portal Updates and Bulk Update Launch
  The team reviewed the DQIM portal user stories, focusing on the bulk update feature which is near completion and planned for launch next week. Additional stories for UAT, E3 deployment, and integration testing were discussed and created to cover validation and approval processes. The bulk update launch will require coordination for ServiceNow RFC and PIP.

• Date Filtering and API Limitations
  Discussion on the date filter and table name filtering revealed current limitations due to backend API constraints. The API requires full table names for filtering, disallowing partial matches. The team considered applying client-side filtering post API data fetch to improve usability. Stories will be added to address these enhancements.

• Status "In Progress" Issue
  A bug was identified where the "In Progress" status returns zero results. A story has been created to investigate and fix this issue.

• New Use Cases and Rule Modifications
  The team is awaiting inputs from Rachana on new use cases, with UMDL currently added. Rule modification stories were created to handle dynamic changes, with plans to add more as they arise. Production support is ongoing.

• Self-Serve Portal Enhancements
  Stories were created for PIV support post-launch, a separate page for new rules, and business justification tabs. Field renaming requests from Rachana were incorporated into the backlog.

• Portro and Multivariate Checks
  Validation stories for multivariate checks are planned. The contour feature is mostly complete.

• AI-Enabled Checks and Use Case Discovery
  Two AI approaches were discussed: RAG (Retrieval-Augmented Generation) with business context for intelligent checks, and CDE (Completeness, Data Accuracy, etc.) checks based on eight dimensions. Initial work will focus on CDE checks using metadata from API calls and a non-AI framework. Use case discovery stories were created to explore LLM access and integration.

• Prioritization and Resource Constraints
  Due to limited frontend resources (one frontend developer), priority is given to DQIM portal and self-serve UI work. Backend work can proceed in parallel. Control and AI-enabled frontend work will come later.

• Kibana Dashboard Enhancements
  The need for a use case filter on the Kibana dashboard was highlighted to allow partners to view metrics by use case instead of all checks collectively. Rachana has documented required changes.

Data Migration and Pipeline Management

• Table Ingestion and ODL Support
  Jason outlined support for batch and ODL ingestion of new tables, especially for finance teams. Current BAU and upcoming tables were noted.

• Talks Integration and Data Pipeline Migration
  Migration from Talks BigQuery to Snowflake was discussed, including setting up pipelines from MariaDB to Snowflake. The current pipeline moves data from MariaDB to BigQuery; the goal is to shift to Snowflake.

• Snowflake Familiarization and Access
  The team will ensure access and comfort with Snowflake. Connection testing with Snowflake, RiA DB, and other systems is planned.

• UI Platform for Pipeline Management
  A new UI platform is planned to monitor pipelines and enable self-service. Scoping exercises and requirement gathering are underway. Hosting options within the Amex network and connectivity between Snowflake, MariaDB, and backend systems are under exploration.

• Network Connectivity Risks
  Challenges include connecting non-MX network data sources to the MX network. Calls with relevant stakeholders are scheduled to assess feasibility.

• Data Migration Wrap-Up
  Finalizing migration efforts is a priority, with no major dependencies noted. Scheduling a meeting with Amman for support and ODL job planning was mentioned.
