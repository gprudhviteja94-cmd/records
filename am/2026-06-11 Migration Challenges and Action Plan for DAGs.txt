Migration and Timeline Challenges for DAGs and Related Processes

• The team has approximately 3 to 4 months to migrate around 330 DAGs before a freeze date. This migration also impacts related processes, including an automatic SQL creation use case developed by Prithvi, which requires changes in database connectivity, code pieces, and file transfer paths.

• There is a mandate to complete the migration on time; delays are not acceptable, and responsibility for any process failures post-migration will not be taken by the team if deadlines are missed.
• The migration involves major changes due to the deprecation of Google Composer by Google, requiring a shift to a new platform (Astronomer).
• Phase two of the migration should start immediately to avoid issues, while phase three requires higher-level approvals and business justification.
• The team discussed the need to create a clear roadmap, estimate effort, and allocate resources without halting ongoing product work already committed in the PI (Program Increment).

• Emphasis was placed on addressing the backlog of tasks, including UI and data migration tasks (Snowflake, GCP to GCP, GCP to AWS), with strict adherence to deadlines and leave planning to avoid resource shortages.
