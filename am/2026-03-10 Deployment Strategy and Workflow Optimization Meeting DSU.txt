File creation, IO patterns, and best practices (CSV / GCS / BigQuery / temp tables)

  • When to create files The manager questioned why files (CSV/Excel) are being created and saved to GCP buckets routinely. It is not recommended to create files for every use case. Instead:
    
    • If data size is small, hold data in memory structures (dictionary/objects) and process without creating files.
    • If data size is large, use temporary BigQuery tables (or use-case folder temp tables) instead of writing files. After processing, delete temp tables via a DAG/task.
    • Only create and store files in GCS when there is a clear requirement (e.g., user needs the data back, SFTP transfer). If files are created for SFTP, keep retention short (examples: 24 hours) and communicate to IAPA any data saved to GCS.

  • Reduce DB calls Code review found multiple DB calls (three separate queries) that could be combined into a single query. Developers must check and consolidate queries where possible.

  • Avoid unnecessary file IO File write + delete adds extra IO overhead and increases throughput cost and complexity. Prefer DB/temp tables for large volumes. If files must be written, ensure downstream processes (IAPA) are informed and consider automated cleanup tasks only when absolutely necessary.
