📒Meeting Outline

Data Quality Rule Migration and Validation

• Stagnant Data Check to Timeliness Check Change  
  The team discussed a late-requested change where all "stagnant data check" entries need to be renamed and treated as "timeliness check" in the UI dropdown and backend. • Field Mapping and Default Values for Migration  
  Various fields such as "null valid," "latest version in," "approve in," "complex in," and "account in" were reviewed for appropriate default boolean values. It was agreed that "approve in" should be true for all records, "complex in" and "account in" should be false. Some fields like "business justification" are to be left blank for now. The "use case ID" mapping requires special handling due to one-to-many relationships.

• Data Migration Script and Issues  
  The current migration approach using direct insert queries was found problematic due to incomplete field mapping and missing records. Sachin and team emphasized the need for a scripted approach that generates SQL inserts with correct parameters and mappings, including the use case ID. Aapa and Prithvi are responsible for updating and validating the migration scripts. The total records to migrate are about 230, with some exclusions.

• Validation and Synchronization with DEC Repository  
  The team reviewed the mapping between the DEC repository and the target Postgres schema, focusing on columns like DQ ID, var name, table name, filter criteria, frequency, and description. It was confirmed that some fields like rule ID, var ID, and table ID are removed and should not be mapped. The team is ensuring that the migrated data matches the DEC repository accurately.

• Connectivity and Availability Concerns  
  Several participants faced internet connectivity issues due to weather conditions, impacting meeting efficiency. Sachin emphasized the importance of being in the office during critical migration phases to avoid delays and ensure continuous support. Backup plans and resource readiness were discussed to mitigate risks from unexpected absences.

• Next Steps and Urgency  
  The team agreed to complete the migration and validation process on the same day. Everyone involved (Prithvi, Aapa, Ather, Kundan) must remain available until confirmation of successful data migration. Sachin stressed the need for prompt closure and readiness to work late if necessary.
