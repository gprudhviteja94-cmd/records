

Detailed Meeting Summary

Meeting: Meeting Recording 20
Date: 1 July 2026
Duration: ~12 minutes
Primary Topic: Migration of complex Data Quality (DQ) rules from the DQ Repository to the DQ Artifacts table and UI support for complex rules.

Overall Objective

The team discussed completing the migration of complex Data Quality (DQ) rules from the existing DQ Repository into the new DQ Artifacts table while ensuring:

No data discrepancies between both systems.
Existing complex rules are preserved without modification.
The UI can identify complex rules and allow editing of the rule description.
Frontend changes are limited only to supporting existing migrated complex rules.
Current Migration Status

Speaker 1 mentioned:

Total DQ rules: 286
Successfully migrated: 230
Remaining rules:
Approximately 40–56 complex rules (discussion referenced different remaining counts)
These remaining records are all complex rules.

The priority is to finish migrating these remaining complex rules.

Major Decisions
1. Complex Rule Description should become Editable

Current behavior:

Rule description is generated/formatted automatically.

New requirement:

For complex rules, the Rule Description should be:

Plain text
Editable
Not automatically generated

Reason:

Many existing complex rules cannot be represented by the template engine.

Instead, the original text should be preserved.

2. Editable only in Modify Mode

Speaker 1 clarified:

The editable Rule Description should only be available when:

Modify Rule

It should NOT be editable during:

Add Rule

Reason:

New rules are expected to follow the simple rule template.

The editable description exists only for supporting migrated legacy rules.

3. Do NOT Refactor Complex Rules

Initially there was discussion about cleaning up:

Filter Criteria
Missing Value checks
Allowed Margin
Conditions

Final decision:

Do NOT modify complex rules.

Instead:

Migrate them exactly as they currently exist.

Reason:

The system is not expected to generate SQL for complex rules.

Therefore there is no benefit in restructuring them.

Migration Guidelines

Speaker 1 instructed:

Migrate data exactly as-is

Do not:

rewrite
simplify
optimize
reformat

Preserve Original Rule Description

Key Takeaways
Around 230 of 286 DQ rules have already been migrated.
The remaining complex rules should be migrated without any functional changes.
Rule descriptions must be preserved exactly as plain text.
Every migrated complex rule must have complex = true, enabling the frontend to display an editable Rule Description.
Editable Rule Description applies only in Modify mode, not during Add Rule.
Maintain consistency between the DQ Repository and DQ Artifacts to avoid data discrepancies.
New production rules are out of scope for this migration and will be handled later.
