Test Request Filtering and CL Verification Process

• Filtering test requests for new features  
  The team discussed the need to filter test requests related to new features that do not require exploration. Vamshi took the lead in explaining the current approach and challenges.

• Agent-based CL extraction and verification  
  The process involves agents extracting Change Lists (CLs) based on paths provided by Subject Matter Experts (SMEs). These paths can be by activity, flow, or functionality. The agent fetches CLs and decides which require verification, passing relevant information to the SMEs.

• Handling discrepancies between agent and human decisions  
  If there is a difference in CLs marked for verification by the agent versus human SMEs, these discrepancies will be analyzed by the team (including RT, Andrew, Gary). The goal is to refine filtering criteria based on this analysis.

• Use of existing app scripts and automation  
  The current CL extraction uses app scripts in sheets, which will continue to be leveraged through the agent.

Filtering Criteria and Folder Path Strategy

• Folder path exclusion for new features  
  One proposed solution is to exclude CLs from specific folder paths related to new features (e.g., voice home, voice calling). If developers specify folder paths that should not be touched, those CLs will be excluded from verification.

• Limitations of tagging CLs for new features  
  The team acknowledged that Google’s infrastructure does not currently support tagging CLs explicitly as new features or NTK (Next To Know) in the code or CL metadata.

• Challenges with regression and new feature overlap  
  Regression fixes and new feature code often reside in the same folders, complicating filtering. The team emphasized the need for absolute path information to differentiate these cases.

• Human intervention and approval  
  Final approval and agreement on filtering criteria need to come from Andrew and Gary. The team will present the existing logic and proposed solutions to them for validation.

Learning and Improving the Agent Model

• Incorporating human decisions into the agent’s learning  
  The agent will learn from ad hoc human decisions that go beyond predefined rules, improving its accuracy over time.

• Suggestion to add tags for new features  
  It was suggested to request Gary to consider adding tags or parameters to CLs to identify new features, which would aid filtering.

• Limitations in schema and CL creation  
  Adding such tags at the code file or CL creation level is currently not feasible due to schema constraints.
