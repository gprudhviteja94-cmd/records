Self-service / Q-Track Automation Demo

  • Self-service automation goal Prithvi demoed a Q-Track self-service automation prototype that generates SQLs automatically from entries in the DQ repository table. The envisioned flow: new requests create entries in the repository table → DAG reads entries daily → generates SQL file(s) for the corresponding table(s) and templates → places generated SQLs into a JCP bucket for review.

  • Supported checks & templates Current implementation supports duplicate and stagnation (stagnant) checks. Duplicate check uses one template; stagnant checks use three templates. Existing requests (~1600) will map to these templates if applicable. New templates would require adjustments (not auto-supported yet).

  • Template mapping logic The automation identifies the appropriate template using description, filter condition, and where clause; the check type in the request (e.g., stagnant, duplicate, null) helps routing. When rules map to templates, the system generates SQL per rule.

  • SQL file generation & append behavior For a given table and frequency (daily/monthly), existing SQL files are identified and new rule SQL is appended to the same file (using appropriate union/unique constructs) so that one SQL file contains all rules for that schedule. If multiple templates are matched for the same table/frequency, the bot appends corresponding rule SQLs into the same main SQL file. This behavior was clarified and agreed upon.

  • DAG and Git integration Current flow: the tool generates SQL files and places them in a folder or JCP bucket for review. Direct Git commits (automated PRs) are not yet implemented due to Git bot access and ADS ID constraints; R&D required to allow commit via bot. DAG conversion is in progress: code can be run from command prompt now and has been modified into a DAG format; impacts to existing DAGs must be considered when enabling automatic modifications.

  • Demo details Prithvi demonstrated running the tool against CSV input representing rule entries, showed generation of SQL files for duplicate and stagnant checks, and how the tool picks existing SQL templates to append new SQL. The output SQL files were previewed and stored in a separate folder for review.
