📒Meeting Outline

Quantra Data Quality Metrics and Threshold Calculation

• Overview of Quantra Metrics
  The team discussed the four types of metrics Quantra handles: onboard metrics, monthly algorithm metrics, daily checks, and monthly checks. Onboard metrics calculate thresholds for newly onboarded DQID rules using one year of historical data. Monthly metrics revise thresholds for existing rules. Daily and monthly checks validate if current data values fall within calculated thresholds, raising anomalies if not.

• Onboard Metric Process and Code Walkthrough
  Sameer demonstrated the DAG code for onboard metrics, explaining how Quantra reads data from the Quadro SQL file to identify new rules (status false) for threshold calculation. The process ignores existing rules with pre-calculated thresholds (status true). The team reviewed how filter criteria are formatted dynamically to avoid SQL syntax errors, especially for edge cases in specific tables like CM11 and CM13. Custom methods adjust the filter clauses based on table-specific requirements.

• Focus Metrics and Aggregation Methods
  The discussion covered how different focus metrics (count, mean, median) are selected based on rule descriptions and data characteristics. Examples were shown illustrating why certain metrics like count or mean are chosen for specific DQIDs. The aggregation involves calculating statistical measures such as mean, standard deviation, skewness, covariance, and autocorrelation functions (ACF7, ACF30) using SQL functions on time series data.

• Dynamic Threshold Calculation and Suppression of False Alerts
  The team emphasized replacing static threshold values with dynamic thresholds calculated via algorithms like Holt-Winters, EWMA, and ARIMA. This approach helps suppress false alerts by accounting for seasonal trends and data variability. For example, credit card bill amounts fluctuate seasonally, and the system adapts thresholds accordingly to avoid unnecessary alerts. The current success rate of false alert suppression is 76%.

• Challenges and Future Improvements
  Concerns were raised about potentially suppressing true alerts due to dynamic thresholding. The team acknowledged this risk and is working on improvements to avoid missing valid alerts. The process includes monthly recalculations to adapt to changing data trends. The current algorithm selection uses sequential if-else logic, which is planned to be optimized.
