📒Meeting Outline

AI-Driven Developer Assistance and Project Automation

• Background and Previous Project (ADAS)  
  The presenter has developed an Agentic Development Assisting System (ADAS) integrated with VS Code IDE, which automates code generation across front-end, back-end, middleware, database, and testing. This tool has been well received by the team and company.

• Current Challenge: Automating Requirement Gathering and Grooming  
  The new project aims to automate the process of collecting and analyzing requirements from various communication channels such as Microsoft Teams chats, emails (Outlook), and calls. The goal is to consolidate these inputs to generate accurate user stories and tasks in Rally, reducing manual effort and improving precision without hallucinations or vague outputs.

• Integration of Multiple Tools and Data Sources  
  The project will integrate data from multiple tools used daily by developers: Teams chats, Rally for task management, Outlook emails, and internal company websites. These sources provide fragmented information about requirements, discussions, and product feedback that need to be unified for better context understanding.

• Use of Large Language Models (LLM) with Project Context  
  To avoid hallucinations, every prompt sent to the LLM will include detailed project context generated by ADAS, such as endpoints, components, database schemas, and overall architecture. This context will be provided as structured data (e.g., JSON) rather than full code to optimize processing time.

• End-to-End Automation Workflow  
  The envisioned workflow includes capturing discussions from chats, emails, and calls (with plans to record and transcribe calls), feeding consolidated text to the LLM, generating Rally tickets with acceptance criteria, and upon product team approval, triggering code generation and pull request creation via ADAS with a single button click.

• Token Usage and Cost Management Strategy  
  Since token consumption and associated costs are a concern, the proposal includes deploying an internal LLM within the company infrastructure (Argus system). This LLM will act as a centralized "brain" for the project, accessed by a designated lead who manages context input and output, reducing the number of users directly consuming tokens.

• Developer Assistance Beyond Rally Integration  
  The project also plans to assist developers by capturing and analyzing team chat messages, especially from group channels related to UI, backend, and product discussions. This data will be stored locally in a lightweight database (e.g., RocksDB or LMDB) with a retention period of about three months to maintain relevant context.

• Notification Center Concept for Developers  
  A notification center will be developed as a side panel or pop-up on developers’ machines (e.g., MacBook) to display project updates such as completed tasks, new stories, and important messages from product teams. This will help developers stay informed about recent changes and organizational updates relevant to their work.

• Rally Board Integration and Output Consistency  
  All outputs from the LLM and automation process will be structured as Rally epics, stories, and tasks to maintain consistency and traceability within the existing project management framework.

• Future Considerations and Challenges  
  Challenges include managing privacy concerns around exposing chat messages, optimizing token usage, and ensuring the LLM processes only high-level context rather than full codebases to reduce latency and resource consumption.
