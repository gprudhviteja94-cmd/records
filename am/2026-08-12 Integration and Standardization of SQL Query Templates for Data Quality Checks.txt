📒Meeting Outline

Integration and Standardization of SQL Query Templates for Data Quality Checks

• Current Template Limitations and Enhancements
  The team discussed the existing four templates used for data quality checks such as length check, pattern check, missing value, and valid value. It was noted that length check is currently missing and could be incorporated. However, not all checks can fit into the existing templates, especially complex or conditional checks. Approximately 600 conditional checks exist, which could be grouped under a single template, while 30 to 70 other checks might require new templates or categorization.

• Automation and SQL Query Generation
  There was a focus on leveraging automation that generates SQL queries for these checks. The question was raised whether the SQL generated by the eight-dimensional (8D) module can be adapted to fit the existing templates or if it should be treated as complex checks. The 8D module currently produces outputs that are not standardized, lacking clear rule descriptions, which complicates direct integration.

• Mapping and Categorization of Checks
  Out of 718 total checks reviewed, only about 40-43 could be mapped to existing check types like valid value or missing value. The majority, especially the 600 conditional checks, require careful analysis to determine if they can fit existing templates or need new ones. The team emphasized the importance of maintaining business value in categorization, avoiding an excessive "others" category.

• UI and Backend Considerations
  The team debated how these checks should be reflected in the user interface (UI). It was agreed that some checks, especially those generated automatically and complex in nature, might remain backend-only without UI exposure. There was also discussion about the need for bulk upload features in the UI to handle multiple checks efficiently, as manual input for hundreds of checks is impractical.

• Future Development and Coordination
  The need to standardize the output of the 8D module to match the format used by the self-serve automation was highlighted. This would reduce manual effort and improve consistency. Coordination among the team members, including Sameer and Kundal, was deemed essential to finalize template creation, modify automation scripts, and ensure the system supports future modifications by users.

Troubleshooting and Processing Issues in Bulk Task Handling

• Task Status and Processing Errors
  Participants reviewed issues related to task processing in bulk, where tasks were marked as completed but errors persisted. It was noted that some tasks remained open despite attempts to close them, and errors appeared in reports and on the DTYM platform. The team tested processing a single record to isolate the problem and observed that errors reduced after refreshing and re-uploading data.

• Access and Permissions
  Admin access was temporarily granted to facilitate troubleshooting, but concerns were raised about giving such access to partners. The team agreed to investigate the root cause of the processing issues and expected values not showing correctly.

• Next Steps in Issue Resolution
  It was decided that further analysis and testing would continue, with follow-up calls planned to resolve outstanding issues. The team emphasized the importance of ensuring that the work basket configuration and group mappings function correctly to allow smooth task processing.
