📒Meeting Outline

Secret Management and Deployment Process

• Secret Management Module Overview  
  The team discussed the process of managing secret keys required for service deployments. Previously, application teams had to coordinate with DevOps to update secret keys on servers. Now, the Control Center provides a Secret Management module where users can add, view, search, and delete secret keys directly for a specific deployment ID and user tenancy. The UI allows adding single or multiple secrets using valid JSON format, with immediate feedback on successful updates.

• Access Control and Multi-Tenancy Challenges  
  Access to the Secret Management module is restricted; not all users have permission to add or modify secrets. For managing secrets across multiple tenancies, users currently need to request Vault admin access via SSO groups, which can be cumbersome. There was a discussion on the need for a new feature to streamline multi-tenancy secret management with a single SSO group request. This requirement will be taken up upon formal submission through leads.

• Security and UI Concerns  
  Questions were raised about the security implications of allowing password search functionality in the UI. It was clarified that the secrets pertain to service or application passwords within a tenancy, not individual user passwords. The UI has minimal front-end validation; backend validations blacklist certain keys. A request was made to share the list of blacklisted or global configuration keys for awareness.

• Technical Issues and Troubleshooting  
  A recent login issue was traced to a CORS (Cross-Origin Resource Sharing) error, which typically occurs when API calls originate from unauthorized URLs. The resolution involved updating secret management configurations for the affected tenancy. The team agreed to share tenancy details to investigate and resolve such issues more efficiently.

Organizational Updates and Administrative Reminders

• Weekend Java Walk-in Drive Recap  
  The team successfully conducted a Java walk-in drive on Saturday, exceeding the expected turnout with 70 participants instead of the targeted 40. Special thanks were extended to Venkatesh Orlu, Pooja, Saurabh, Sandeep, and Kavishri for their support, both onsite and virtually.

• Hierarchy and Career Path Changes  
  Updates were shared regarding changes in reporting structures to improve alignment and visibility. The new career path feature on the Hub platform was introduced, allowing employees to view role-specific expectations and growth trajectories. Managers will guide employees through goal setting based on these career paths in the coming weeks.

• HackerRank Assessment and Skill Development  
  The organization aims for all employees to achieve at least 80% on HackerRank assessments. Those scoring below 40% have been given retake opportunities, and others scoring between 40-70% will receive further assessments to improve their scores. Continuous skill refreshment is encouraged as these scores impact appraisals.

• Status Report and Leave Calendar Compliance  
  Employees were reminded to keep their status reports and leave calendars updated well before month-end (preferably by the 21st to 26th). This practice facilitates better planning and reduces last-minute coordination challenges.

• Policy Acceptance and Training Compliance  
  A reminder was issued about timely acceptance of organizational policies and completion of mandatory trainings. Delays in compliance may negatively affect individual performance evaluations.

• Synchrone Laptop Usage and Security Updates  
  Employees were advised to connect their Synchrone laptops to the network at least once every 10 days to receive critical security patches and updates. If the laptop is not in use, returning it is an option. Otherwise, it should be kept on and connected for a few hours weekly, especially when working from home, to avoid critical security risks and IT escalations.
