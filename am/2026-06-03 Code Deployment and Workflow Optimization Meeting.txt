Code Deployment and Testing Workflow

• Codebase Migration and Verification  
  The team discussed moving the current code base to the main branch specifically for the escalation email feature. After migration, verification is required to ensure that processes B40 and B45 are running correctly. The goal is to complete this verification and closure within one to two hours.

• Lumi and Data Transfer Implementation  
  The next task involves working on the Lumi part and the Data Transfer (DT) flow using the common utility created. The requirement is to pull all details from the Loyalty Status table, generate a CSV or Excel file, and upload it to the SFTP server. Passwords should not be stored on the report until admin access is enabled. The implementation should be straightforward and completed within an hour.

• Environment and Storage Guidelines  
  Access to the Google Cloud Storage (GCS) environment will be granted soon, but no buckets or tables should be created without prior confirmation. Files must be stored in the project space, not the composer space, to avoid confusion. The team was reminded to clarify any doubts regarding project space vs. composer space with Answers.

• Data Format and File Generation  
  The data is a full refresh daily, so a simple "select *" query suffices without altering columns. There was a discussion about file formats: although JSON was initially considered to avoid CSV parsing issues, the team agreed that CSV or Excel formats are acceptable. The Airflow get operator can be used to generate CSV files directly from queries without additional coding.

• Documentation and Reporting
