Mapping and Updating Rule Descriptions

• Duplicate Check Type Review  
  Prithvi filtered duplicate check types and found all existing rules can be mapped to the new template, though some descriptions require updating to fit a consistent structure.  
• Description Content and Structure  
  The new description should explicitly mention the variable names (e.g., CM11, RESI User ID) to clarify what fields must be unique. Descriptions should not contain column names but should reflect the inputs clearly.  
• Alignment on Description Updates  
  Sachin and the team agreed to update descriptions to include specific variable names and align all rules under a consistent format.  
• Avoiding New Columns  
  Instead of creating new columns for descriptions, existing description fields will be updated by replacing unspecified placeholders with actual variable names.  
• Impact on Aggregation and Other Processes  
  Sameer will be invited to assess any impact on aggregation processes that rely on descriptions. Threshold checks are separate and unaffected by this change.  
• Template Usage for Configuration  
  Prithvi will continue to use variable name and table name columns directly for configuration where descriptions lack detail, ensuring templates remain effective without relying solely on descriptions.  
• Handling Unique Count Exceptions  
  A unique count rule with a specific value (e.g., 21) is handled via a condition inside the template. This exception was discussed and confirmed as acceptable.
