📒Meeting Outline

Data Quality Rule Description Templates and SQL Query Standardization

• Review of Description Templates  
  Rachna shared the current status of description templates for data quality (DQ) checks, highlighting 29 distinct templates identified from existing rules. She explained the creation of standard description templates based on inputs from the intake form, excluding the threshold check which integrates with Ponto. The templates dynamically incorporate user inputs such as variable names and percentage thresholds for missing value checks. Rachna noted some wording changes from previous descriptions to improve clarity and usability for UI configuration.

• Updating Existing Rule Descriptions  
  Sachin raised concerns about regenerating descriptions for the existing thousand-plus rules. It was clarified that the system will provide users with options to view and modify descriptions, and that existing descriptions will be migrated to the new template format through simple queries. Arthur will estimate the time required for updating existing descriptions once the template is finalized. The team agreed that finalizing the template is a prerequisite before proceeding with bulk updates.

• Duplicate Templates and SQL Query Differences  
  The team discussed the presence of multiple templates for similar checks, specifically duplicate checks, where two templates exist with slightly different SQL queries but similar English descriptions. Prithvi demonstrated the differences in SQL logic between the two duplicate check templates, showing that one is essentially a negation of the other with additional conditional checks for multiple variables. The discussion focused on whether both templates are necessary or if one can cover both use cases by handling single or multiple variables via a CONCAT function.

• Proposal to Minimize Templates  
  It was proposed to test the CONCAT function with a single variable input to confirm if one template can replace the two. If successful, the redundant template will be removed to simplify maintenance. The team acknowledged that multiple developers over the years have contributed to the rule set, leading to variations in SQL queries even for similar requirements. The goal is to standardize and minimize the number of templates while ensuring all use cases are covered.

• Next Steps for Review and Additional Check Types  
  The team planned to finalize the duplicate check template by the next day for re-review. Following that, they will proceed with the missing value check template. Additionally, the valid value check was identified as another area with multiple similar scripts (around 13), which will also be reviewed for consolidation. The approach will be to compare scripts at the SQL level and reduce the number of templates to the minimum necessary.
