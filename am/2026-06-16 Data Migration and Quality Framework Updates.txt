📒Meeting Outline

Data Migration and DQ Repository Updates

• Null Values and Column Usage  
  The team agreed to keep certain UI fields as null since they are not required in the Data Quality (DQ) rule runs. Columns such as variable type (continuous/discrete) are manually entered and not fetched from metadata, so they can be discontinued. Date variables are needed but handled via filter conditions.

• Data Migration Status and Portal Readiness  
  Data migration is nearing completion, expected within a few hours. The portal deployment is targeted for end of the week or early next week. Existing use cases have been migrated, but some use case names need clarification or renaming (e.g., PRJP to Insurance). Duplicate or unclear use cases were discussed, with a call for seriousness on data insertion and a dedicated resource assigned.

• DQ ID Management  
  Concerns were raised about large gaps in DQ IDs. A proposal was made to fix a base number and increment sequentially (N+1) to avoid huge gaps. Backup and mapping of old to new DQ IDs will be maintained before changes. The priority remains to migrate existing data and make the portal live before ID restructuring.

• Threshold Checks on UI  
  Threshold checks will not be implemented on the UI initially. There is a plan to migrate threshold data to the ASTV database for reference, but modification capabilities will be disabled to prevent unauthorized changes. The focus is on letting the checks go live first.

• Bulk Update and Production Deployment  
  Bulk update testing is ongoing. A deployment of AMGM script in production has removed duplicate records from DQ positive data. Data migration discrepancies are being resolved, with closure expected soon.

CD Framework and AI-Based DQ Checks

• Current Status and Expectations  
  The CD (Control Deficiency) framework is evolving. Initially based on usage logs, it now incorporates KRI (Key Risk Indicators) scripts and QTRI variables. The process is manual, with a parser created for KRI SQL scripts. The work is divided into identifying CD variables, cleaning and creating DQ checks using AI frameworks, and deploying/validating these checks over a few weeks.

• Immediate Needs and Ambiguities  
  The immediate requirement is to persist identified CDs in a Lumi warehouse table for sharing with other teams. However, clarity is lacking on how data will be fed into this table and the exact role of the current team. The CD identification framework by Antares is on pause due to ambiguity.

• AI-Based QTRI Checks  
  The AI-based QTRI DQ checks framework by Charmi is finalized and expected to be completed within four weeks. Validation of these checks will be done by the Tech team before implementation.

• Next Steps and Coordination  
  Metadata sharing from Purna is awaited to proceed. The team plans to meet again to clarify requirements and set expectations. The deployment of the CD framework to the E3 environment is planned for early July, with RFC readiness required.

Metadata, Use Cases, and Environment Migration

• Metadata and IIQ Groups  
  Metadata input from JSON for new tables is pending. IIQ groups are still being created and can be modified post-pipeline creation. There is urgency to complete IIQ groups before certification to avoid recertification.

• Composer to Astronomer Migration  
  Migration from Composer to Astronomer is requested to be included in phase 1 to allow sufficient validation time. The environment provisioning is awaited to start migration. Delay in migration phases could impact processes and require higher-level approvals.

• Use Case Verification  
  Some use cases lack proper naming or clarity on ownership. A follow-up call is planned to verify and finalize use case details.

• Alerts and Validation  
  TLS alerts are being monitored; no recent alerts have been received. Validation will continue for a few more weeks to ensure system stability.
