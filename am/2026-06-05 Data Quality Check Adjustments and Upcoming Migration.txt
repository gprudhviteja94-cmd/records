Data Quality Check Conditions and Adjustments

• Condition on Account Credit Variable  
  The discussion focused on the condition for the "account credit" variable, which should not have values between 300 and 850. It was agreed to ask Arthur to update this condition accordingly.

• Handling of Filter Conditions and Check Types  
  There was clarification that some suggestions were not related to filter conditions. The team decided to keep certain checks marked as complex for now, especially those involving threshold checks and missing values. For example, Walmart Plus values should not be zero on any day, but this check will be skipped for now.

• Duplicate Checks  
  The "count of duplicate CM 15" was discussed and agreed to be categorized under duplicate checks. Some changes to check types were needed to reflect this correctly.

• Boolean Value Checks  
  Checks involving boolean values (true/false) were reviewed. It was clarified that these should only accept true or false values, despite some negative statements in the descriptions.

• Handling of Null and Missing Values  
  Several checks related to null values and missing data were reviewed. It was noted that some checks expect less than 0.5% missing values, and others require zero percent nulls. Some descriptions and check types need updating to reflect these expectations accurately.

• Future Date and Threshold Checks  
  Checks involving future dates and threshold values were marked as complex and deferred for further discussion. These include conditions like "future date less than zero" and length-based validations.

• Review of Remaining Complex Checks  
  After filtering and adjustments, 59 checks remain marked as complex, reduced from 96. The team plans to address the remaining complex checks in the following week.
