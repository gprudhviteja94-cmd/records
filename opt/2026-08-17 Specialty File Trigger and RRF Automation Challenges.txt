📒Meeting Outline

Specialty File Trigger and Azure Blob Storage Issue

• File Trigger Problem  
  The team discussed an issue where specialty files with headers were not triggering the Azure Blob Storage event as expected. Curtis explained that the C# code used to push files required a specific file closure method to trigger Azure functions properly. Despite files being pushed, the Azure trigger was not activating because the files were not arriving on the Azure Blob Storage side. The problem was not with the trigger itself but with the files not being delivered after a credentials issue was resolved on August 12th. Since then, new specialty list IDs have been created without corresponding files arriving to trigger jobs.

• File Delivery and Trigger Workflow  
  Curtis clarified that the file arrival triggers his job, and since files are missing, the trigger is not broken. The team agreed to investigate why files are not arriving and planned a follow-up meeting to align on the process and responsibilities. It was noted that Databricks cannot directly connect to on-prem SQL Server, complicating alternative data pulling methods.

RRF Request Automation and Manual Intervention

• Manual vs Automated Processing  
  The discussion covered whether new RRF (Request for Repricing Flow) requests require manual intervention. It was confirmed that except for some automation on line 6, most RRF requests need manual action within the RA system. The Petal system picks up requests automatically only after certain conditions are met, but currently, Petal does not scan the new ITBR database where Curtis pulls data, only the Datamark database.

• Petal System Integration and Code Changes Needed  
  To fully automate, Petal needs code changes to scan the ITBR database and monitor the RF tag SK table populated by Curtis’s jobs. This integration is feasible but not yet implemented. Stephanie was asked to create a story for this enhancement. The team discussed the complexity of setting up this integration and the priority of these changes.

• Testing and Access for Automation Requests  
  The team agreed that to test end-to-end automation, non-production RA team members need access to act on RRF requests manually. Curtis suggested cloning existing requests to simulate new ones for testing. The team acknowledged the dependency on RA intervention for the flow to progress and discussed the possibility of development team members getting access to facilitate testing.

Automation Request Status and Job Processing

• Current Status of Automation Jobs  
  Curtis shared that automation jobs run every five minutes and pull data from MongoDB tables. Some automation requests submitted recently were stuck in the "ETL automation prep" status, indicating the job responsible for advancing their status was not functioning as expected.

• Job Processing Delays and Fixes  
  The delay in processing was attributed to job scheduling and sequence, with some jobs running before others. Curtis and the team agreed this is a minor issue expected to be fixed shortly. Once fixed, the automation requests should progress through the expected statuses, enabling further testing.

Reporting and Output for RRF Requests

• Output Reports and Underwriter Access  
  The output from RRF requests varies but often includes PNL and RPT reports. Underwriters access these reports via links stored in a specific table. The team discussed ensuring these reports are accessible and integrated properly with the RA system.

• API Integration and Future Work  
  The team mentioned ongoing work to integrate APIs for report access and other functionalities, with plans to explore these as the project progresses.

Summary of Dependencies and Next Steps

• Dependencies on RA and Petal Teams  
  The automation process depends heavily on RA team actions and Petal system enhancements. Coordination with these teams is critical for progress.

• Planned Follow-ups and Story Creation  
  Stephanie will create a story for Petal code changes. Curtis and Kevin will investigate file delivery issues and automation job fixes. A follow-up meeting between Curtis and Kevin is planned to clarify responsibilities and next steps.
