📒Meeting Outline

Overview and Context of ADAS Bootstrap Agent Tool

• Introduction to ADAS Tool and Purpose  
  Zeeshan introduced the ADAS Bootstrap application developed on GitHub Copilot, designed to create multiple custom AI agents to automate software development tasks. The tool supports front-end, back-end, testing, and orchestration agents, aiming to streamline project development by generating code based on existing repositories and user prompts. The tool is currently in a work-in-progress phase and intended for internal use and feedback.

• Functionality and Agent Architecture  
  The system creates about 16 generic agents covering different development tasks such as front-end coding, back-end coding, test case generation, and code review. An orchestrator agent coordinates these agents. Agents use multiple LLMs (Large Language Models) like Claude Sonnet for reasoning and GPT Codex for code generation, optimizing token usage by leveraging context memory files instead of repeatedly scanning the entire codebase.

• Memory and Context Management  
  The tool generates and maintains memory files (e.g., context.md, lessons.md, instructions.md) that store project-specific knowledge such as components, routes, coding patterns, bug fixes, and user preferences. This memory enables continuity across development phases and among different team members, allowing seamless handoffs without re-learning the project context.

Detailed Technical Walkthrough and Usage

• Setup and Project Integration  
  The tool scans the user's workspace to detect projects and prompts the user to select the project and type of setup (full agent team or standalone agent). It supports different project scenarios such as greenfield development, enhancements, or migrations. The setup process generates agents and memory files inside the project folder but currently does not push these files to GitHub automatically; sharing is done via zipped folders or pending GitHub integration approval.

• Wave-Based Development Process  
  Development is structured in waves: foundation and framing, backend API and business logic, frontend pages, and final inspection and verification. Users can specify which waves to execute (e.g., frontend only) by providing instructions to the orchestrator. Each wave includes validation steps and allows user feedback to correct or refine generated code before proceeding.

• Handling Manual Interventions and Code Changes  
  While the agent-driven process is mostly automated, users can intervene manually between waves to make changes. However, manual changes outside the agent workflow are not automatically learned by the system unless explicitly fed back through prompts. The tool encourages iterative feedback to improve accuracy and reduce repeated issues.

• Token Usage and Limitations  
  The tool optimizes token consumption by using memory files and selecting appropriate LLMs for different tasks. Token usage is roughly 30-40% less compared to normal prompting. However, access to GitHub Copilot or Codex is mandatory as the tool is built on these platforms. Some team members currently face access issues due to enterprise restrictions, which impacts usage.

• Collaboration and Context Sharing  
  The memory files generated by the tool enable multiple developers to work on the same project by sharing these files via GitHub or zipped folders. This ensures consistent context and coding standards across team members and phases without reprocessing the entire codebase.

Challenges and Open Questions

• GitHub Copilot Access Restrictions  
  Several participants reported losing access to GitHub Copilot due to enterprise policy, which restricts the ability to use the ADAS tool. This is a critical blocker for adoption and requires escalation or alternative solutions.

• Code Commit and Deployment Automation  
  Currently, the tool generates code but does not automatically commit or deploy it. Manual commits and validations are recommended to maintain control over code quality and integration. Deployment agents exist but are not fully integrated into the workflow.

• Sharing and Version Control of Agent Files  
  Discussion on best practices for sharing generated agent files and memory context within teams is ongoing. Options include pushing to GitHub or sharing zipped folders, pending organizational approval.

• Handling Specific UI or Business Logic Changes  
  The tool allows specifying constraints in prompts (e.g., no UI changes) to avoid unwanted overrides. However, very specific or complex business logic still requires manual coding by developers.

📋Overview

• ADAS Bootstrap tool creates multiple AI agents to automate software development tasks using GitHub Copilot and multiple LLMs.
• The tool builds project-specific memory files to maintain context, enabling iterative development and collaboration across team members without reprocessing the entire codebase.
• Development follows a wave-based approach allowing phased execution and validation of frontend, backend, and integration tasks.
• Manual intervention is possible but requires explicit feedback to the system to avoid repeated issues.
• Token usage is optimized but requires active GitHub Copilot or Codex access, which is currently a limitation for some users.
• Sharing of generated agents and memory files is under discussion, with options including GitHub push or manual sharing.
• The tool does not yet automate code commits or deployments; these remain manual steps.
• The team plans to share the tool repository once organizational approvals are secured.
