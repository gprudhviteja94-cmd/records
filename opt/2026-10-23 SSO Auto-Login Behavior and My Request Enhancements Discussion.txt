📒Meeting Outline

SSO / Login Behavior

• Observed behavior
  The application is auto-logging in via SSO (SS4). When the user signs out of the page but remains signed in to SS4, reopening the page logs the user back in without additional verification. The tester demonstrated this behavior using a normal browser session and attempted to reproduce in incognito/private mode.

• Reproduction suggestions and verification
  To verify whether the auto-login is coming from existing SS4 tokens, it was suggested to:
  • Test in a browser profile that has never signed into SS4.
  • Test using an incognito/private window (to avoid existing SS4 session tokens).
  • Attempt login with a different user account or paste the direct download hyperlink in incognito to see whether it prompts for credentials.

• Evidence and confirmation
  The tester noted that in incognito the app still reached an SSO prompt and asked which user to use; when an existing SS4 session exists, the app bypasses additional authentication. The group agreed this behavior indicates SS4 functioning as intended (single-sign-on), but asked to capture evidence (screenshots/logs) when reproducing in a clean profile or incognito for clarity.

• VPN / external-access concern
  Discussion raised an earlier security issue (RPT) where vulnerabilities occurred when accessing without VPN. Participant asked whether downloads or access can be attempted from systems outside the VPN and whether the app behaves differently. Action: test from a non-Optum environment or coordinate with Sattam to try access without Cisco VPN to validate behavior and security implications.

Download / "My Request" Functionality

• Current limitation
  In the "My Request" section multiple-select / bulk-download functionality is missing. User can only download files one-by-one; bulk select checkboxes and a "Download All" option are not present in this section (though similar functionality exists on other pages, e.g., Find Files page or for files in a cool tier).

• User expectation
  The user expects consistency: if multiple-select and "Download All" exist elsewhere (Find Files), the same should be provided in "My Request" so users can select multiple requested files and download them together.

• Possible causes and considerations
  • Browser settings / permission issues may prevent multiple-file downloads in one go; however the UI lacks checkboxes in My Request to initiate bulk actions.
  • The My Request page was previously designed for tracking individual requests (order-tracking), and one participant noted business or design reasons might have kept it single-download only.
  • The team agreed this is an enhancement (UX/feature), not a code bug per se, and requires design/requirements confirmation before implementation.

• Related UX improvements
  • Add checkboxes for multiple selection in My Request.
  • Add a "Download All" bulk action/button.
  • Ensure permissions prompt guidance for multi-file downloads (browser permission behavior).

Pagination, Ordering, and Scalability of My Request

• Scalability concern
  The My Request page will grow large over time (many requests/files from underwriters); without pagination or ordering, the page will become unwieldy.

• Requested features
  • Implement pagination to avoid loading very large result sets on a single page.
  • Add ordering/sorting capability (e.g., by request date) to find requests quickly.
  • Consider displaying ordered request history (DSE-style ordering) to aid tracking.

• Timing and priority
  The change is classified as an enhancement. The speaker requested not to start implementation before confirming with Sattam — do not begin work before 8 (unclear if "8" is time or date; likely before coordinating with Sattam). Team to discuss priority after confirmation.
