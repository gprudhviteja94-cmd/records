📒Meeting Outline

Automation progress and demo

• UI automation using Excel tool
  • Implemented first-phase UI automation on staging via Excel-based tool/test suite. Global properties hold environment URL; switching to Dev requires only URL change.
  • P1 functional test cases for RPT module added to a test suite; can run entire suite (10 cases) or individual cases. Execution produces a dashboard with pass/fail/not run counts, completion status, and duration. Example run took ~45 seconds and validated tabs like RA Output and Rates per Quantity.
  • Intended to support UAT/regression by sharing execution reports. API automation has not started yet; focus remains on UI/functional coverage.

• Data comparison automation (Excel/CSV)
  • Automated validation of Dev-delivered spreadsheets using a Python script that ingests two CSVs and outputs an HTML comparison report.
  • Report details: total rows/headers/columns validated; number of matches/mismatches; per-header mismatch counts; exact mismatches with row/column identification and values from both files; tolerant to column order differences by matching on column names.
  • Current workflow converts XLSX to CSV manually; Pandas libraries are now available and will be integrated next to compare XLSX directly and handle merged cells and grouped headers (e.g., “Group” + “Detail” combined into single header).
  • Example results showed 35 mismatches detected within ~20 seconds on a large dataset. The script is generic for export outputs and intended to work across multiple tabs; currently file-level (not multi-tab-aware) and single-pair execution.

Challenges, scope, and enhancements

• Handling complex sheets and tabs
  • Rate Buildup tab flagged as the most complex for layout; current blocker: unable to download its Excel from UI. Team to obtain the file and validate the script on it as a priority.
  • Existing issues include merged cells, grouped headers, and column sequence differences. Enhancements planned: unmerge handling, header normalization, direct XLSX comparison via Pandas.

• Gold-standard validation and UAT approach
  • Need a “gold standard” expected output set to validate against. Options discussed:
    • Use existing production tool outputs as expected once January production deployment occurs.
    • In the interim, use curated “automation test data” on staging; compare daily runs and perform RCA for deltas (XPaths/data issues vs. app changes).
    • For features like BioSIMs, consider before/after comparisons to establish truth sets.
  • Agreement that UAT requires a clear source of truth for actual vs. expected; planning needed post-scope confirmation.

• Scaling comparisons and reporting granularity
  • Desire to batch-compare many files (e.g., 100 client/scenario RA Output files) by pointing the tool at two directories and auto-matching pairs.
  • Reporting improvements requested:
    • High-level summary at group level (e.g., PPA, AWP, etc.): per-group match percentage, counts of matches/mismatches.
    • Overall sheet match percentage and concise rollups before detailed row/column diffs.
    • Include only necessary cell references; since column names are stable, emphasize semantic headers over coordinates.
  • Suggestion to trial an image comparison tool (shared previously) for visual validation where layout matters.

Execution status and responsibilities

• Ownership and contributions
  • Akanksha led core comparison logic; Vaishali handled report generation and the UI automation test suite configuration.
  • Team open to feedback; focus on delivering a solid first release for testing and then iterating with enhancements.
