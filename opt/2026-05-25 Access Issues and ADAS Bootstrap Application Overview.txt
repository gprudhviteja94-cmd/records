Introduction and Overview of the ADAS Bootstrap Application

• Purpose and Functionality  
  The ADAS system is a custom-built bootstrap application designed to generate 16 specialized agents that automate end-to-end development tasks, including front-end, back-end, integration, testing, and code review. It supports both new application development and enhancements to existing projects by creating memory files that store project context, coding patterns, and architecture decisions.

• Agent Types and Roles  
  The 16 agents are categorized into four types: analytical agents, front-end agents, back-end agents, and infrastructure agents. An orchestrator agent coordinates interactions among these agents, managing tasks such as connecting front-end to back-end APIs and reviewing code for adherence to standards.

• Memory and Context Management  
  The system maintains several markdown files (context.md, patterns.md, lessons.md, decisions.md, components.md) that act as memory for the agents. These files store API endpoints, coding patterns, bug fixes, architectural decisions, and component usage to ensure consistent code generation and learning from past issues.

Implementation Details and Workflow

• Bootstrap Setup and Repository Structure  
  The bootstrap application exists as a separate repository containing commands to generate agents and extract context from existing projects. It supports both greenfield projects and enhancements by analyzing existing codebases to create memory files automatically.

• Code Generation and Collaboration  
  Generated agents work locally within the project folder (under a .github directory) and do not automatically push code changes or create pull requests. Multiple developers can collaborate by sharing the agent repository, allowing the system to learn from collective inputs and maintain consistent coding standards.

• Wave-Based Development Approach  
  Code generation is structured in sequential "waves" to manage dependencies and testing effectively. For example, wave 1 creates skeletons, wave 2 handles routing and connectivity, wave 3 develops UI code, wave 4 generates test cases, and wave 5 performs self-review to ensure compliance with coding standards and test coverage.

• Customization and Extensibility  
  Users can create custom agents tailored to specific use cases, such as a Figma agent that converts Figma designs into code components. The system supports different LLMs (Large Language Models) optimized for various tasks, e.g., Codex for code generation and Claude Sonnet for analytical tasks, reducing token usage and improving efficiency.
