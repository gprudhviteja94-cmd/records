📒Meeting Outline

Usage and Adoption of ADAS Framework

• Current Adoption Status Across Teams  
  Subha confirmed that CKM team has started using ADAS by creating skill files but primarily uses Codex for development work. The setup for ADAS is done, but Codex is preferred due to its simpler prompt interface. Rishabh from RPD shared that while initially using ADAS for test analysis, issues with continuous regeneration of test files led him to switch back to Copilot prompt, which improved productivity significantly. Rohit confirmed active use of ADAS orchestrator for UI, JobWorker, and API tasks. Weibo and others noted that ADAS is more beneficial for large changes, while Copilot is preferred for small or isolated repo changes.

• Reasons for Preference of Codex or Copilot Over ADAS  
  The main reasons cited include simplicity of direct prompting in Codex, better control over context in Copilot, and issues with ADAS regenerating files unnecessarily. Some users felt ADAS sometimes altered coding patterns unexpectedly, leading to discomfort. The token consumption and time efficiency were also factors, with Copilot being faster for small tasks. However, ADAS provides a consistent framework and project context, which is beneficial for large-scale changes and maintaining coding standards.

• Understanding the Intent and Benefits of ADAS  
  Shikant emphasized that ADAS was introduced to create a common AI-DLC framework across teams to ensure consistency and efficiency. Pawan explained that ADAS maintains project-specific coding patterns and context, unlike Copilot which lacks project context and requires multiple prompt iterations. ADAS creates skill files that represent project knowledge, enabling more accurate and standardized code generation.

• Technical Clarifications on Context Usage  
  There was discussion about whether Codex or Copilot uses the context files generated by ADAS. Subha and JK clarified that Codex UI can utilize these context files if placed in the appropriate folder (.Codex), but GitHub Copilot does not inherently use them. David suggested verifying if Copilot leverages these files since they reside in the GitHub repo. It was agreed that the context files are a one-time setup and can be used by multiple tools, but integration varies.

• Feedback on ADAS Agents and Improvement Areas  
  Pawan mentioned recent additions like Prompt Tuner and Figma agents to ADAS, though some features lack token access. David suggested reviewing the configured agents to ensure they meet use case goals and tuning them if necessary. The team acknowledged the need to improve ADAS based on feedback and planned to discuss enhancements in the next meeting.

📋Overview

• CKM team has set up ADAS but prefers Codex for development due to ease of use.
• RPD team initially used ADAS but reverted to Copilot prompt for better productivity on test cases.
• ADAS is more effective for large-scale changes and migrations; Copilot preferred for small, isolated tasks.
• ADAS provides project context and coding standards, reducing iteration and token usage compared to Copilot alone.
• Codex can use ADAS-generated context files if properly configured; GitHub Copilot does not automatically use them.
• Recent ADAS improvements include new agents, but further tuning and feedback incorporation are needed.
• The team recognizes the importance of a unified framework and plans to evaluate and improve ADAS accordingly.
