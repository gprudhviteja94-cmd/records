📒 Meeting Outline

Dynamic UI schema and dropdown behavior

• Dropdown value issue and field types:
  Observed a dropdown opening without showing values. The field had a string value while UI expected option objects. Agreed to standardize field types/values.

• Schema-driven UI:
  Proposed moving from manual per-field mapping to a schema-driven approach. The UI should read a JSON schema from the backend (labels, types, options, dependencies) so adding new fields only requires backend updates.

• Optional vs Required Handling:
  Schema should encode optional/required fields to enforce validation dynamically without hardcoding.

Backend contract and JSON structure

• Backend-provided JSON schema:
  Backend will send a structured JSON (list of objects or keyed by field names) containing metadata.

• Dependent Fields Representation:
  Nested dependencies will be represented inside field definitions containing conditions and child schemas.

• Consistency and Parsing:
  JSON contract must be consistent and easy to parse, avoiding custom UI logic for individual fields.

Current implementation status and scope

• Existing pages and latest page alignment:
  Work on some cost pages has started. Need to align schema-driven UI with the latest page architecture to avoid rework.

• Prototype-First Approach:
  Agreed to prototype the schema UI layer first to verify feasibility and address edge cases (nested dependencies, array inputs).

• Scope and Change Management:
  Since the schema approach is a major change, the team will prioritize read-only functionalities (labels, types, options, required, dependencies) first.

Data specifics and examples

• Example: ARR/Run-rate field:
  The ARR/Run-rate section has dependent child fields that should only render based on parent state. This will be the pilot use case.

• Arrays vs Objects Debate:
  Deciding whether to receive fields as lists (to preserve order) or keyed objects. Lean towards lists with stable keys.

• Validation and Logic Separation:
  Keep validation logic on the backend; UI should render and validate based on schema hints.

📋 Overview of Key Takeaways

• Dropdown options/values must come from backend schema to prevent empty value bugs.
• Adopt schema-driven UI to remove manual field mapping.
• Backend will provide JSON schema including labels, types, options, required flags, and dependencies.
• Dependent fields will be nested inside parent schema conditions.
• Prototype the schema UI first and pilot with the ARR/Run-rate section.
