📒Meeting Outline

Security Enhancements for TDD and UH Agent

• Google Security Recommendations Overview  
  The team discussed required updates to the Test Design Document (TDD) and the UH agent to comply with Google's security recommendations. Key security controls include using the Orcus agent framework, which requires no additional implementation as it already supports detailed audit logging.

• Principle of Least Privilege  
  Agents must operate with the minimum necessary permissions. This is already in place and only needs to be explicitly declared in the documentation.

• Robust Prompt Injection Defenses  
  The team reviewed general strategies to defend against prompt injection attacks. Each agent must describe in its TDD how it mitigates prompt injection, although there are no Google-specific test cases. This is mandatory for approval.

• Mandatory Security Assurance Testing  
  Agents will be onboarded to Google's Code Rare platform for security assurance testing. This process has been initiated for the CL verification and test execution agents.

• Emergency Stop Mechanism (Kill Switch)  
  A critical feature to immediately halt all agent activities and sub-agents if something goes wrong. This hard stop should terminate ongoing tasks and bring agents offline. It must be included in all agents' TDDs.

• Rate Limiting and Throttling  
  Implementation of a circuit breaker and token bucket algorithm is required to control agent request rates. Teams are advised to incorporate these mechanisms into their agents.

• Human in the Loop  
  Google recommends having human oversight in agent operations. While some agents currently lack this, teams are encouraged to explore ways to include human in the loop for security compliance.

• Continuous Monitoring  
  Agents should implement continuous monitoring or propose solutions if not currently in place. This is part of the security policy requirements.

• Launch and Security Review Process  
  The NSEC AI team has been engaged to initiate launch and security reviews for all agents.

Discussion on Specific Agent Scenarios

• Control Limitations in Self-Healing Agents  
  Some agents, such as those triggered by TFA without direct user interaction, currently lack control mechanisms like emergency stop or human in the loop. The team agreed to explore possible solutions for these cases.

• Integration and Individual Adoption Concerns  
  For agents accessed via test execution master agents, existing controls suffice. However, if agents are adopted individually, additional security features like emergency stop and human in the loop must be implemented.

• Prompt Injection Defense in Integrated Agents  
  Agents integrated with others must still document their own prompt injection defenses in their TDDs to ensure comprehensive security coverage.

• Documentation and Formatting  
  Teams were reminded to update their TDDs carefully, maintaining format and font consistency while incorporating the new security points.
