📒Meeting Outline

AI Agent Development Standards and Governance

• Security and Trust Requirements Discussion centered on how AI agents have been given excessive power without proper cost controls, ownership, or governance. This has led to production launch delays, security review rejections, unexpected billing spikes, and teams losing trust in AI systems. The session aims to address these issues by providing a stage-by-stage approach for building AI agents with proper governance.
• Developer Responsibilities and Framework Covered the comprehensive responsibilities for developers, DevOps engineers, and QA teams in AI agent development. Emphasized building secure and ethical agents, defining clear requirements, choosing appropriate LLMs with cost optimization in mind, and maintaining proper orchestration logic using appropriate GCP services.
• Deployment Approaches Two main deployment approaches were discussed: Agent Engine-based deployment and Orcas development/deployment. Agent Engine is preferred for rapid prototyping and MVP activities with enterprise-scale specifications. Orcas is used for Google's internal pre-production and production environments with specific internal tools and automation.

Roles and Performance Metrics

• Team Goals and KPIs Developers must achieve 90% task completion accuracy and reduce agent execution latency. DevOps engineers need to ensure 99% uptime availability, implement cost-effective infrastructure, and achieve infrastructure-as-code compliance. QA teams should reach 90% automated test coverage and ensure 60% of P0/P1 bugs are fixed before release.
• Deliverables by Role Developers deliver high-quality modular Python code and integration pipelines. DevOps engineers provide fully automated CI/CD pipelines, infrastructure scripts, and monitoring dashboards. QA teams deliver automated test scripts, detailed bug reports, and UAT sign-off reports.

Development Lifecycle Stages

• Trust and Readiness Planning Critical first phase requiring agents to be built only in approved projects, respecting regional logging and data rules, designing with audit assumption, and never bypassing security controls for speed. Example given of a bank building a loan-related AI agent with proper regional restrictions and data governance.
• Architecture and Agent Design Agents must be broken down into small, focused components with clearly defined roles. Developers should maintain orchestrator layers, enable context sharing between agents, and avoid creating monolithic agents that do everything. Code size should not exceed certain thresholds (mentioned size "L").
• Identity and Access Control Every agent must have a unique identity with minimum access policies applied. Time-based or rule-based access controls should be implemented, and all actions must be traceable and auditable.
• Model and Prompt Management Models and prompts are treated as production assets, not experiments. Prompts must be stored centrally with proper version control in source code repositories. Sensitive instructions require special security measures.

Technical Implementation Details

• Authentication and Security Discussion about Titan USB security keys being mandatory enforcement that cannot be bypassed. For production deployments, Borg (equivalent to Jenkins) will be used with scheduled cron jobs, eliminating the need for manual security key authentication.
• Google-Specific Libraries Google3-based packages and libraries must be used instead of standard Python imports. RPC and Stubby protocols are required for connecting to internal libraries, providing enhanced security with keyless authentication.

📋Overview

• AI agents require strict governance, security standards, and clear ownership to prevent production delays and cost overruns
• Three key roles (Developers, DevOps, QA) have specific responsibilities and KPIs for successful AI agent delivery
• Two deployment approaches available: Agent Engine for rapid prototyping and Orcas for internal production environments
• Development must follow four critical stages: Trust/Readiness, Architecture Design, Access Control, and Model Management
• Google's security requirements including USB keys and specific libraries are mandatory and cannot be bypassed
• All code, prompts, and configurations must be version controlled and auditable
• Agents should be modular, focused components rather than monolithic solutions
